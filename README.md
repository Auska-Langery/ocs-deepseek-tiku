# OCS DeepSeek 本地题库

给 **OCS Desktop（ocsjs 桌面版）** 用的本地题库服务：OCS 把题目发过来，程序调用 **DeepSeek** 作答，并把答案存进本地题库文件，下次遇到同一道题直接秒答、不再花钱调接口。

- 零依赖：只要有 Node.js 18+，不需要 `npm install`
- 只监听 `127.0.0.1`，数据全部留在本机
- 自带网页管理台：测试答题、管理题库、填 API Key、一键生成 OCS 题库配置
- 支持单选、多选、判断、填空；图片题不支持（DeepSeek 是纯文本模型）

---

## 这个项目要解决什么问题

### 1. OCS 的题库都是别人的

OCS 本身不带题库，得自己去接。能接的基本只有两类：付费/查不到题的第三方题库，或者自己录。于是常见的情况是——题搜不到、答案不准、还时不时限流。这个项目把题库换成自己的：**没有就用 DeepSeek 现场做，做过的存下来，下次直接命中**。题库就是本机一个 `data/bank.json`，随时能导出成 CSV 自己看。

### 2. 「接 DeepSeek」的坑比想象中多

真正动手时踩到的都是 OCS 内部实现的坑，不是调一下 API 就完事：

| 坑 | 现象 | 这里的处理 |
| --- | --- | --- |
| 跨域 | 网页里 `fetch('http://127.0.0.1:8787')` 直接 `TypeError: Failed to fetch` | 题库配置改用 `GM_xmlhttpRequest`，走扩展后台，绕开跨域与混合内容限制 |
| 答案被切碎 | 代码里的 `#include` 变成 `include` | OCS 的 `splitAnswer` 会把 `#` 当分隔符，代码里的 `#` 一律写成 `&num;`（渲染仍是 `#`，但不会被切） |
| 换行全丢 | 编程题挤成一行、`<stdio.h>` 消失 | 富文本框是 `innerHTML` 写入，所以答案按 HTML 给：换行转 `<br>`、`<` `>` `&` 转义 |
| 判断题不认字母 | 返回 `A` 不生效 | 判断题只认「对/错/正确/错误/√/×」这类词，不能给选项字母 |
| 一道大题多个小问 | 只填一个空，或者整题不填 | OCS 把整道大题当「一道填空题」发过来，只往一个框里写一次；这里按题号顺序把小问逐个答完，并把最后一问单独放进 `box` 字段 |
| 段数不匹配就一个字都不填 | 页面上什么都没发生 | OCS 的 `resolveCompletion` 要求「答案段数 = 页面元素数」，而服务端看不到页面结构，所以干脆提供一个 `handler` 直接在页面里定位题干、写入文本框（见 `OCS题库配置-直接写入版.json`） |

### 3. 想改就能改

整个服务是几个 `.mjs` 文件，没有构建、没有框架、没有 `node_modules`：`server.mjs` 管 HTTP，`lib/deepseek.mjs` 管调模型，`lib/answer.mjs` 管答案格式化，`lib/text.mjs` 管题干解析，`lib/bank.mjs` 管本地题库。想改提示词、换模型、加题型，直接改文件重启就行。

## 一、三步跑起来

### 1. 准备 Node.js

已安装可跳过。没装的话去 <https://nodejs.org/> 下载 LTS 版安装（一路下一步即可）。
装完在「开始菜单 → 命令提示符」里输入 `node -v`，能显示版本号就说明好了。

### 2. 启动题库服务

双击本目录下的 **`启动题库.cmd`**。

窗口里出现类似下面的内容就说明启动成功，并且会自动打开管理台网页：

```
OCS DeepSeek 本地题库
管理台   http://127.0.0.1:8787/
答题接口 http://127.0.0.1:8787/api/answer
```

> 这个黑窗口就是题库服务本身，**不要关**。想停止服务就关掉它（或按 Ctrl+C）。
> 想让它开机自动启动，可以把这个 cmd 的快捷方式丢进
> `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup` 文件夹。

### 3. 填 DeepSeek API Key

1. 打开 <http://127.0.0.1:8787/>（启动时会自动打开）
2. 点顶部 **「设置」** 标签
3. 把 API Key（`sk-` 开头）粘贴进「API Key」输入框，点 **「保存设置」**
4. 点旁边的 **「测试连接」**，出现「连接成功」就说明通了

> Key 保存在本目录的 `config.json` 里，只在本机，不会上传到任何地方。
> 没有 Key 也能启动，只是每次答题都会提示「尚未配置 DeepSeek API Key」。

## 二、在 OCS 里接入

### 方式 A：直接粘贴（推荐）

1. 打开管理台 → **「接入 OCS」** 标签
2. 点 **「复制配置」**（页面会按你当前的地址/端口自动生成 JSON）
3. 回到正在挂课的页面，打开「OCS 网课助手」悬浮窗 → **通用 → 全局设置 → 题库配置**
4. 关键一步：题库配置这一行的**主按钮**打开的是「官方题库」一键获取面板（只会列出你已装的题库，比如言溪题库，**没有输入框**）。
   要手动填，必须点按钮右侧的 **「⋯」→「自定义题库」**
5. 在「题库配置填写/修改区」里粘贴 JSON → 点 **「保存配置」**，按钮文字会变成「N 个可用题库」
6. 刷新挂课页面，再开始答题

> 没有「⋯」按钮的版本：说明没配置官方一键获取渠道，直接点主按钮就是手动配置弹窗。

> 粘贴的新配置会**整体替换**原来的题库。想同时保留旧题库，就把两份配置放进同一个数组里（中间加逗号）；
> 注意 OCS 是**并发**请求所有题库，DeepSeek 每题都会跑一次、会消耗额度。

也可以直接复制本目录 **`OCS题库配置.json`** 里的内容（默认端口 8787 时与页面生成的完全一致）。

配置长这样：

```json
[
  {
    "name": "DeepSeek 本地题库",
    "homepage": "http://127.0.0.1:8787/",
    "url": "http://127.0.0.1:8787/api/answer",
    "method": "post",
    "type": "GM_xmlhttpRequest",
    "headers": { "Content-Type": "application/json" },
    "data": {
      "title": "${title}",
      "options": "${options}",
      "type": "${type}"
    },
    "handler": "return (res) => { if (!res || !res.answer) { throw new Error((res && res.msg) || '本地题库未返回答案'); } return [res.question, res.answer]; }"
  }
]
```

几个必须注意的点：

- **`type` 用 `GM_xmlhttpRequest`**。OCS 桌面版内置了「脚本猫」，它给脚本提供了 `GM_xmlhttpRequest`：请求由扩展后台代发，不受页面跨域、CSP、混合内容限制。
  用 `fetch` 从 https 的答题页直接请求 `http://127.0.0.1` 会被浏览器拦掉，面板上表现为 `TypeError: Failed to fetch`（本题库的接口也开了 CORS，实在没有 GM 环境时把 `type` 改回 `"fetch"` 也能用）。
- `headers` 里的 `Content-Type` 要自己写，OCS 发请求时不会替你补。
- `data` 里的 `${title}`、`${options}`、`${type}` 是 OCS 会替换的占位符，不要改成别的写法。
- 题库**只能有一个**时也必须是 JSON 数组（外面那对 `[]` 别丢）。想再加一个题库，用 `###` 分隔多个 JSON 数组。

### 方式 B：确认配置生效

在 OCS 里随便做一道题，看管理台「测试台」下方的调用记录：
有记录且 `source` 是 `deepseek` 或 `cache`，就说明 OCS 已经把题目发过来了。

## 三、管理台能干什么

| 标签页 | 用途 |
| --- | --- |
| **测试台** | 手动输入题干/选项，直接看 DeepSeek 返回什么、耗时多少、有没有命中缓存 |
| **题库管理** | 搜索、按题型筛选、分页浏览；手动新增/删除；导入导出 JSON、CSV；清空 |
| **设置** | API Key、模型、思考模式、温度、超时、访问令牌，以及三个答题策略开关（见下） |
| **接入 OCS** | 生成并复制 OCS 题库配置，附常见问题 |

答题记录会写进 `data/logs/`（按天分文件，默认保留 30 天）；「最近调用」列表是内存里的最近 30 条。

### 设置里的三个「答题策略」开关

| 开关 | 默认 | 作用 |
| --- | --- | --- |
| 要求「截图 / 画图 / 上传图片」的主观题留空 | **关** | 打开后，只有**主观题**（简答/填空/问答）命中才留空；选择题、判断题即使题干里提到截图也照常作答 |
| 带图且只能靠图作答的主观题留空 | **关** | 同上，只对主观题生效 |
| 简答 / 编程题答案转成 HTML | 开 | 见下面「简答 / 编程题为什么会挤成一行」 |

> 两个「留空」开关默认关着是有原因的：网课题干里经常夹着整道大题的提交说明
> （“运行程序截图，截图需包含源代码和运行结果”），靠关键词判断很容易把该做的小题一起留空。
> 现在改由模型自己判断 —— 只有「答案必须做成一张图、完全没有文字作答途径」时才会留空。

跳过的题目**不会写进本地题库**，也不会消耗 token；OCS 面板上会显示跳过原因。

判断“要不要留空”时会绕开这些情况：题目说「贴源代码 / 粘贴代码」、说「不要截图」、说「参考答案是截图」——
这些都说明有文字作答的余地，会正常给答案。所以像「阅读理解大题下面是几个小题」的结构，
小题是单选/判断时不会被连带跳过。

## 四、它是怎么答题的

1. OCS 发来题干 + 选项 + 题型
2. 先查本地题库（题干归一化后做键，忽略空格、标点、【单选题】这类前缀和题号）
3. 命中就直接返回，`cached: true`，**不消耗 token**
4. 没命中才调 DeepSeek，然后：
   - **单选/多选**：返回选中选项的**原文**（例如 `B. 443`），多选用 `#` 连接
   - **判断**：返回「对 / 错」或对应选项原文（OCS 的判断匹配只认对错词，给字母无效）
   - **填空**：返回填空文本，多个空用 `#` 连接
5. 答案写回题库，下次同题直接命中

为什么返回「选项原文」而不是字母 `B`？因为 ocsjs 的匹配顺序是
「归一化精确匹配 → 相似度 → 纯字母兜底」，原文匹配排在最前面、最不容易错；
而选项文本里如果本身带 `#`、`;` 这类 OCS 的分隔符，程序会自动降级成字母作答，避免被切开。

**同题不同题型也能复用**：同一题干如果在别处已经答过（比如上次是单选、这次是判断），
会把历史选项文本重新对到当前选项上，能对上就直接用。

### 简答 / 编程题为什么会挤成一行、`#include` 会丢

OCS 的简答/编程题是把答案**当成 HTML 塞进富文本编辑器**的（`body.innerHTML = answer`），于是：

- 答案里的换行 `\n` 被 HTML 当成空白 → 整段挤成一行
- `#include <stdio.h>` 里的 `<stdio.h>` 被当成 HTML 标签 → 直接消失，只剩 `include int main()`
- OCS 内部还会用 `#` 当「多个空」的分隔符 → `#include` 会被切成 `include`

所以本服务对简答/编程题做了两件事（对应 `lib/answer.mjs` 的 `formatCompletionAnswer`）：

- **编程题**：整段转义（`<` → `&lt;`、`&` → `&amp;`），换行写成 `<br>`，代码里的 `#` 写成 `&#35;`
- **多行简答**：只把换行写成 `<br>`，并把 `#` 换成全角，避免被当分隔符切碎
- **单行填空**（比如 `80#443`）：保持纯文本，`#` 仍然是多空分隔符

**编程语言**：网课题干经常不写语言，模型可能答成 C++ 或 Python。设置页新增「编程题默认语言」（默认 `C`），
题目没写明时按这个语言生成，C 语言课就不会再收到 `#include <iostream>` 那一套了。

这几条转换是 OCS 官方自己也在用的做法（雨课堂的 `fillYktUEditor` 就是把 `\n` 转成 `</p><p>`、把 `& < >` 转义后再写入编辑器）。
如果哪天的编辑器不接受 HTML（答案里出现字面的 `<br>`），到「设置 → 答题策略」把「简答 / 编程题答案转成 HTML」关掉即可。

## 五、目录结构

```

├─ 启动题库.cmd          双击启动（自动探测 Node、自动打开管理台）

├─ server.mjs            本地服务（HTTP 路由、答题流程、缓存、日志）
├─ selftest.mjs          自检脚本（55 项，纯 mock，不花钱）
├─ lib/
│  ├─ text.mjs           题干/选项归一化、选项拆分、题干指纹
│  ├─ answer.mjs         提示词、模型输出解析、格式化成 OCS 认识的答案
│  ├─ deepseek.mjs       DeepSeek 调用（并发、超时、重试、模型回退）
│  ├─ bank.mjs           本地题库（读写 JSON、导入导出、防抖落盘）
│  └─ config.mjs         配置读写（默认值 ← config.json ← 环境变量）
├─ public/index.html     管理台（单文件，无外部依赖）
├─ data/
│  ├─ bank.json          本地题库（自动生成）
│  └─ logs/              按天分的答题日志
└─ config.json           你的配置 + API Key（首次保存时生成）
```

## 六、自检

改了代码或怀疑服务不正常时，在本目录执行：

```bat
node selftest.mjs
```

它会用 mock 模式在临时目录起一个服务，跑 55 项检查（选项解析、四种题型、缓存命中、
CORS 预检、题库增删改查、导入导出、清空、简答/编程题的 HTML 转换、跳过截图题等），最后打印 `全部通过`。
自检**不调用 DeepSeek**，不消耗额度，也不会动你的 `data/bank.json`。

## 七、常见问题

**Q：双击 cmd 一闪而过 / 提示找不到 Node.js**
说明系统没装 Node 或没进 PATH。装好 Node 后重开 cmd 再试；本脚本也会去
`D:\New Folder\node.exe`、`%ProgramFiles%\nodejs\node.exe` 等常见位置找。

**Q：端口 8787 被占用**
先试 `重启题库.cmd`（它会找到占用 8787 的进程并结束掉，再启动新版）。
如果还是不行，改本目录 `config.json` 里的 `"port": 8788`（没有这个文件就先在设置页保存一次），
重启服务；再去管理台「接入 OCS」重新复制配置（URL 里的端口要跟着改）。

**Q：改了代码 / 更新了程序，怎么让新版本生效？**
双击 `重启题库.cmd`，或者关掉原来那个黑色命令行窗口再双击 `启动题库.cmd`。
新版启动时会顺便请求旧实例的 `/api/shutdown` 让它自己退出，所以大多数情况下直接双击 `启动题库.cmd` 也能换上新版本。

**Q：简答题答案挤成一行、编程题的 `#include` 丢了、`<stdio.h>` 不见了**
已修复，见上文「简答 / 编程题为什么会挤成一行」。如果 OCS 某次改版后又出现，
到「设置 → 答题策略」把「简答 / 编程题答案转成 HTML」开关来回切一下试试。

**Q：为什么有些题 OCS 显示「该题要求交截图/图片，文字交不了，已按要求留空」？**
1.1.2 起默认**不会**自动跳过任何题，这句话只会出现在「题目确实必须交一张图片、完全没有文字作答途径」的时候。
如果连该做的小题也被留空，说明关键词误判或模型判断失误 —— 到「设置」确认版本是 1.1.2 以上（双击 `重启题库.cmd` 换新版），
或者在「答题策略」里确认两个跳过开关是**关闭**状态。

**Q：一个大题下面好几个小题，为什么整题都没做？**
1.1.1 修过一次（跳过规则只作用于主观题），1.1.2 又把两个开关默认关掉了，正常不会再出现。
如果还遇到，去「设置」确认版本是 1.1.2 以上，或者把两个跳过开关都关掉。

**Q：题干里带图（“如图”“下图”）也被跳过了，可我想让它猜一个答案**
「设置 → 答题策略」里关掉「题干带图的题目留空」即可。但 DeepSeek 看不到图，猜的答案大概率是错的。

**Q：OCS 里答不出来，提示「题库连接失败」**
按顺序排查：
1. 黑窗口是不是关掉了（服务没在跑）；
2. 浏览器打开 <http://127.0.0.1:8787/health> 是否有 JSON；
3. 配置里的 `type` 是不是 `GM_xmlhttpRequest`、`url` 端口对不对；
4. 管理台「设置」里点「测试连接」看 Key 是否有效、余额是否充足。

**Q：顶部黄色提示「当前题库配置暂不支持图片、公式等题目处理」**
不是报错，是 OCS 的图片题优化兼容性提示（源码注释写明“仅提示，不限制”）：它发现你开了
「图片题优化」，而这个题库配置没声明 `${images}` / `${suggestion_title}` 等字段。
DeepSeek 本来也看不了图，点提示右上角 **×** 关掉即可（同一份配置不会再弹）；
想彻底消失，去「通用 → 全局设置 → 自动答题设置」把 **图片题优化** 取消勾选。

**Q：题库那一行显示 `TypeError: Failed to fetch` 怎么办？**
只有两种原因：
1. 题库服务没在跑 —— 双击 `启动题库.cmd`，看黑窗口里有没有「题库管理台」字样；
2. 配置里的 `type` 还是 `"fetch"` —— https 答题页直接 `fetch` 本地地址会被浏览器拦掉，改成 `"GM_xmlhttpRequest"` 即可。
判断服务是否正常：浏览器打开 <http://127.0.0.1:8787/api/ping>，出现 `{"ok":true,...}` 就是好的。

**Q：为什么 `GM_xmlhttpRequest` 在桌面版能用了？**
OCS 桌面版内置「脚本猫」扩展，它给脚本提供了 GM 接口（OCS 自己的「题库延迟」探测就是用它发 HEAD 请求的）。
请求由扩展后台代发，天然绕过页面的跨域 / CSP / 混合内容限制。本题库服务端也开了 CORS，
所以万一某个环境没 GM 接口，把 `type` 改回 `"fetch"` 也能用。

**Q：图片题 / 录音题**
不做。往 OCS 传图片需要 POST 里引用 `${images}`，DeepSeek 也没有视觉能力。

**Q：提示「DeepSeek 输出被截断（达到 max_tokens）」**
代码类大题太长，模型一次写不完。1.1.2 起会自动把上限翻倍重试（4000 → 8000，最多 8192），
大多数题能一次过；还把配置里的 `maxTokens` 调大即可（管理台「设置 → max_tokens」）。
如果题目特别长（比如“成绩管理系统完整代码，含五个功能”），可能要等 60 秒以上，
而 OCS 单题只等 60 秒 —— 这种题建议手动做。

**Q：OCS 是 https 页面，请求 `http://127.0.0.1` 会被拦吗？**
用 `fetch` 会被拦（面板显示 `TypeError: Failed to fetch`），所以默认配置改用 `GM_xmlhttpRequest`：请求由脚本猫扩展后台代发，不经过页面，
既不受跨域限制，也不受混合内容限制。服务端本身也回好了 CORS 预检（含 `Access-Control-Allow-Private-Network: true`），两种方式都能跑。

**Q：能不能给局域网里别的设备用？**
默认只监听 `127.0.0.1`。真要开：启动参数 `--host 0.0.0.0`（或在 config.json 里改 `host`），
同时**务必**在设置页填一个「访问令牌」，否则同网段任何人都能白嫖你的额度。

**Q：数据会不会上传？**
不会。只有题干/选项会发给你自己配置的 DeepSeek 接口，题库、日志、Key 全在本机。

## 八、接口文档（想自己接别的工具时看）

### `GET|POST /api/answer`

| 参数 | 说明 |
| --- | --- |
| `title` / `question` / `q` | 题干，必填 |
| `options` | 选项，换行分隔，如 `A. 80\nB. 443`；填空/判断可省 |
| `type` | `single` / `multiple` / `judgement` / `completion`，也可传中文「单选题」 |
| `hint` | 可选，额外提示（会拼进提示词） |

返回（**出错也是 HTTP 200**，用 `code` 区分，OCS 才不会把整个题库判死）：

```json
{
  "code": 1,
  "msg": "本地题库缓存",
  "question": "下列哪个是 HTTP 默认端口？",
  "answer": "A. 80",
  "type": "single",
  "typeLabel": "单选题",
  "letters": ["A"],
  "source": "cache",
  "cached": true,
  "confidence": 0.95,
  "ms": 2
}
```

`answer` 为空字符串表示没答出来，`msg` 里是原因（例如未配置 Key、模型超时）。

### 其它

| 接口 | 说明 |
| --- | --- |
| `GET /health` | 健康检查，含版本、端口、模型、是否有 Key、题库条数 |
| `GET /api/stats` | 统计（查题数/命中数/命中率/AI 调用次数） |
| `GET /api/bank?q=&type=&page=&size=` | 题库列表 |
| `POST /api/bank` | 新增/更新一条；`{"all":true}` 清空 |
| `DELETE /api/bank/:id` | 删除单条 |
| `POST /api/import` | 导入 `{entries:[...], mode:"merge"\|"replace"}` |
| `GET /api/export?format=json\|csv` | 导出 |
| `GET /api/logs?limit=30` | 最近调用记录 |
| `GET\|POST /api/config` | 读/写配置（Key 只回显掩码） |
| `POST /api/config/test` | 测试 Key 是否可用 |
| `GET /api/ping` | 连通性探针，不碰 AI、不写题库 |
| `GET /api/access?limit=50` | 最近访问记录（排查「OCS 到底有没有把请求发过来」） |
| `POST /api/shutdown` | 关闭服务（仅本机可调，重启/更新时用） |

## 九、版本

`1.1.8`（当前）——
- **不再拆小问、不再拼段数，改成「顺着题目顺序把小问全部答出来」**：OCS 把一道含 (1)(2)(3) 的大题整题当 `completion` 送过来，服务端看不到页面结构，无论怎么猜段数都可能对不上。现在直接把整题交给模型，按题号顺序逐问作答（`(1) C` / `(2) B` / `(3) 完整代码`），由页面里的 handler 决定写进哪个框
- 配套的 [OCS题库配置-直接写入版.json](OCS题库配置-直接写入版.json)：handler 按题干定位 `.questionLi`，把答案解码后直接写进第一个 `textarea`（或富文本 `iframe`）并补发 `input`/`change` 事件，**完全绕开 OCS 的段数匹配**
- 两个「跳过」开关继续默认关闭，不再自动留空任何题
- 自检 66 项全通过

`1.1.7`——
- **混排大题的段数改成自适应轮换**：1.1.6 按「选项数 + 1」拼了 9 段，但用户页面上仍然一个框都不填，说明真实的页面元素数不是 9（一个选项可能占 2 个元素）。服务端看不到页面 DOM，只能试：候选 `[选项数+1, 选项数×2+1, 选项数+2, 选项数×2+2, 选项数, 选项数×2]`，同一道题每被问一次就换下一个。段数不匹配时 OCS 的 `resolveCompletion` 直接返回 `false`、什么都不做，所以多试没有副作用
- 顺序是 `选项数×2+1` → `选项数+1` → `选项数+2` → `选项数×2+2`；`选项数+1` 已实测不成立，所以排到第二顺位
- 复用旧缓存时会把历史里已经拼成 JSON 数组的答案还原成纯文本（`unwrapComposite`），不会越包越多层
- 响应里多了 `slots` 字段，管理台调用日志也能看到，方便对账
- 自检仍是 67 项

`1.1.6`——
- **修复「混排大题一个字都不填」**：像「阅读理解」这种一道大题里既有 2 个单选、又有一个填空的，OCS 会整题按 `completion` 处理，而它的 `resolveCompletion` 要求「答案段数 = 页面元素数」（8 个选项 + 1 个空 = 9 段），段数对不上就一个框都不填。现在这类题会把答案拼成 9 段 JSON 数组：前 8 段是选项占位，最后一段才是代码
- 混排题的代码用**纯文本**给出（真实换行、`#` 不转义），因为目标框是 `textarea.md`，塞 HTML 会原样显示实体字符
- 自检扩充到 67 项

`1.1.5`——
- **修掉「明明答出来了，页面上却是空的」**：OCS 会把同一道题问两次（一次标题保留换行、一次把换行压成空格），而「要截图就留空」的判断排在缓存之前，第二次请求直接返回空、把第一次的答案覆盖掉。现在**先查缓存再判留空**，第二次直接返回同一份答案
- 明确是写代码的题（「编写函数」「实现程序」「main 函数」「截图需包含源代码」等）**不再留空**，照常给代码；只有真的要交图片/拍照/手写的题才留空
- 自检扩充到 65 项

`1.1.4`——
- 修复 `Failed to execute 'querySelector' on 'Element': 'span.saveSingleSelect[data="…"]' is not a valid selector`：OCS 会拿答案文本拼 CSS 选择器去找选项，所以**带选项的题必须按选项作答**。现在只有「没有选项的主观题」才走拆小问逻辑，答案里也不会再出现代码/HTML
- 选项文本含 `"` `[` `]` `\` 时一律改用字母作答（这些字符会让 OCS 的选择器语法出错）
- 题干上限从 4000 字放宽到 20000 字，并会自动砍掉超星塞进标题里的 UEditor 初始化脚本、压平大量制表符，修复「题目过长（超过 4000 字）」- 代码里的 `"` 和反斜杠也转成 `&quot;` / `&bsol;`：OCS 会把答案拼进 `[data="…"]` 属性选择器，双引号会直接让选择器语法错误
- 自检扩充到 64 项

`1.1.3`——
- **复合题（一道大题下含 (1)(2)(3) 多个小问）现在只回答文字作答框对应的那一小问**：OCS 把整道大题当成一道题发过来、只往一个框里写答案，以前会把 `（1）C （2）A （3）代码` 全塞进同一个框；现在先按编号拆小问，再挑出要文字/代码的那一问单独作答，其他小问的字母不再混进来
- 代码里的 `#` 改用 `&num;` 转义：OCS 的 `splitAnswer` 一定会按 `#` 切分答案，之前 `&#35;include` 会被切成 `& 35;include`、`<stdio.h>` 也会散架；`&num;` 渲染出来仍是 `#`，但不会被切
- 「需要交截图/拍照/画图就留空」重新**默认开启**：判断只看作答框对应的那一小问，不会再误伤同一大题里贴代码、填文字的小问
- 请求日志里保存的题干/答案放宽到 400 字，排查问题时能看清整段大题
- 自检扩充到 63 项
